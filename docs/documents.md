# Documents Module

**Documents** внутренний прикладной модуль Core API (.NET 10)
Отвечает за регистрацию загрузки корпоративных документов,
выдачу короткоживущих presigned URL для прямой передачи файла в объектное хранилище
и подтверждение успешной загрузки с фиксацией метаданных.

Модуль не выполняет извлечение текста, embeddings, семантический поиск и генерацию ответов.
Эти обязанности относятся к целевой архитектуре Enterprise RAG и подключаются отдельными компонентами.

## Назначение и границы ответственности

Documents развивается как модуль **модульного монолита** Core API, а не как отдельный микросервис.

| Компонент                | Ответственность                                                                                                                       |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------- |
| **Core API / Documents** | Регистрация документа, доверенный `OwnerId`, проверка входных данных, переходы состояний `PendingUpload` / `Uploaded`, HTTP-контракты |
| **PostgreSQL**           | Постоянные метаданные документа: владелец, имя файла, MIME-тип, размер, версии, статус, ключи объектов, контрольная сумма             |
| **MinIO**                | Хранение бинарных оригиналов во временной области загрузки и под неизменяемым ключом версии после подтверждения                       |
| **Клиент**               | Получение presigned URL и прямая загрузка файла в MinIO; не задаёт `OwnerId` и не определяет права доступа                            |

Модуль не публикует задания в RabbitMQ,
не запускает Document Ingestion Worker,
не вызывает AI Orchestrator для embeddings
и не выполняет retrieval.

Поиск по документам и RAG остаются за рамками текущей реализации.

## Сценарий Register -> Presigned PUT -> Confirm

```text
Клиент
   │
   │ POST /documents  (аутентифицированный запрос)
   V
Core API / Documents
   ├── ICurrentUser -> trusted OwnerId
   ├── Проверка FileName, ContentType, Size
   ├── Document.CreatePending (PendingUpload)
   ├── Presigned URL для временного ключа MinIO
   └── Сохранение метаданных в PostgreSQL
          │
          │ 201 + RegisterDocumentResponse (uploadUrl)
          V
Клиент
   │
   │ PUT {uploadUrl}  ->  MinIO (временный объект)
   V
Клиент
   │
   │ POST /documents/{documentId}/confirm
   V
Core API / Documents
   ├── Проверка OwnerId (документ чужого владельца -> 404)
   ├── StoreOriginal (временный ключ -> постоянный ObjectKey)
   ├── ConfirmUpload + Checksum
   └── Status = Uploaded
          │
          V
       DocumentResponse
```

## Безопасность

Идентификатор владельца документа определяется Core API через
ICurrentUser и не принимается от внешнего клиента.

Documents endpoints требуют аутентификации.

До внедрения OIDC используется Development Authentication,
доступная только в локальном окружении Development.
В Production этот механизм запрещён.

Доступ к документу другого владельца не раскрывает
информацию о документе.

## Проверка реализации

- 51 автоматический .NET-тест успешно пройден.
- Docker Compose и автоматические миграции проверены.
- Проверен сценарий Register -> Presigned PUT -> Confirm.
- Подтверждена идемпотентность повторного Confirm.
- Проверены HTTP 400, 401 и 404.
- Проверено отсутствие изменения состояния чужого документа.

## Текущие ограничения

RabbitMQ, Document Ingestion Worker, extraction, embeddings,
pgvector indexing и semantic retrieval будут подключены
на следующих этапах Enterprise RAG.
