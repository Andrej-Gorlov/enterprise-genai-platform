# AI Orchestrator

**AI Orchestrator** самостоятельный сервис обработки задач ИИ в составе Enterprise GenAI Platform. Он предоставляет типизированный HTTP интерфейс для операций над текстом и изолирует вычисления на Python от прикладной логики основного сервера.

В действующей конфигурации сервис выполняет проверку текста и семантическое сравнение с использованием локальной модели векторных представлений. Архитектура допускает развитие вычислительных функций без переноса моделей и библиотек машинного обучения в .NET Core API.

## Назначение и границы ответственности

Разделение между Core API и AI Orchestrator строится по характеру задач, а не по принципу «отдельный сервис на каждую функцию».

| Компонент | Ответственность |
| --- | --- |
| **Core API (.NET 10)** | Публичный интерфейс платформы, прикладные модули, проверка входных данных, интеграционные контракты и доступ к PostgreSQL |
| **AI Orchestrator (Python 3.13)** | Выполнение специализированных вычислений над текстом, управление жизненным циклом модели и выдача результата через HTTP |
| **PostgreSQL + pgvector** | Постоянное состояние платформы; векторное расширение предусмотрено для дальнейших сценариев поиска |
| **Шлюз языковых моделей** | Предусмотренная архитектурой точка обращения к генеративным моделям; в текущем составе сервисов не развёрнут |

AI Orchestrator **не хранит пользовательские чаты**, не управляет правами доступа к документам и не вызывает внешнюю генеративную языковую модель. Вычисление векторных представлений отдельная операция машинного обучения, а не обращение к LLM.

Полноценный поиск по документам, формирование контекста RAG, генерация ответов и обработка документов относятся к целевой архитектуре платформы. Их наличие не следует выводить из реализации семантического сравнения.

## Взаимодействие компонентов

```text
Клиент
   │
   │ POST /ai/semantic-similarity
   V
Core API (.NET 10)
   ├── Проверка запроса
   ├── IAiOrchestratorClient / HttpClientFactory
   ├── Ограничение времени ожидания и передача отмены
   └── X-Correlation-ID
          │
          │ POST http://ai-orchestrator:8000/semantic-similarity
          V
AI Orchestrator (FastAPI)
   ├── Контракт запроса (Pydantic)
   ├── EmbeddingService
   │      └── SentenceTransformerModel
   │             └── all-MiniLM-L6-v2 (CPU)
   └── Косинусное сходство
          │
          V
       { "score": ... }
          │
          V
Core API → HTTP-ответ клиенту
```

Core API обращается к Python через типизированный клиент `IAiOrchestratorClient`. Внешние потребители используют маршрут Core API; прямой доступ к Python нужен главным образом для локальной диагностики и изолированных проверок.

Связь синхронная, по HTTP. Брокер сообщений и фоновая очередь в этой операции не участвуют.

## Внутреннее устройство

Реализация построена на **FastAPI**, **Pydantic** и библиотеке **SentenceTransformers**. Основные обязанности разделены между HTTP слоем, службой вычисления близости и адаптером модели.

| Элемент | Роль |
| --- | --- |
| `main.py` | Создание FastAPI приложения, жизненный цикл, маршруты и промежуточное ПО Correlation ID |
| `models.py` | Модели запросов и ответов, ограничения входных данных |
| `dependencies.py` | Получение сервисов через внедрение зависимостей |
| `EmbeddingService` | Получение векторов, проверка результата модели и вычисление косинусного сходства |
| `SentenceTransformerModel` | Адаптер к `SentenceTransformer`, преобразующий результат модели в числовые векторы |
| `service_info.py` | Метаданные сервиса для проверки состояния |

Модель `sentence-transformers/all-MiniLM-L6-v2` загружается **один раз при запуске приложения** в обработчике жизненного цикла FastAPI (`lifespan`). Созданный `EmbeddingService` хранится в состоянии приложения и предоставляется маршруту через зависимости. Повторная инициализация модели для каждого HTTP запроса не выполняется.

Операция семантического сравнения определена как синхронный обработчик FastAPI (`def`). FastAPI выполняет такой обработчик в пуле потоков, не блокируя цикл асинхронных событий на время синхронного вызова модели.

Взаимодействие службы с моделью организовано через отдельный интерфейс. Это позволяет проверять вычисления и HTTP контракты с подменой зависимости, без загрузки весов модели в каждом тесте.

### Семантическое сравнение

Для двух входных текстов модель вычисляет векторные представления одним вызовом `encode`. Используемая модель выдаёт **384 мерные векторы**; служба проверяет корректность набора векторов и вычисляет косинусное сходство:

$$
\operatorname{sim}(a,b)=\frac{a\cdot b}{\lVert a\rVert\,\lVert b\rVert}
$$

Результат число, обычно находящееся в диапазоне от -1 до 1. Более высокое значение означает большую близость представлений в пространстве данной модели. Это **не вероятность**, не оценка истинности утверждения и не универсальная мера качества текста. Порог принятия решений должен определяться конкретным прикладным сценарием, а не задаваться внутри сервиса для всех потребителей.

## HTTP интерфейс

Сервис предоставляет три маршрута:

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| `GET` | `/health` | Проверка доступности и состояния приложения |
| `POST` | `/validate-text` | Проверка текста и получение его длины |
| `POST` | `/semantic-similarity` | Семантическое сравнение двух текстов |

### Проверка состояния

`GET /health` возвращает сведения о сервисе, его версии и состоянии:

```json
{
  "name": "ai-orchestrator",
  "version": "0.1.0",
  "status": "healthy"
}
```

Приложение начинает обслуживать HTTP запросы после завершения `lifespan`, поэтому доступность маршрута также подтверждает успешное окончание начальной загрузки модели. Этот маршрут не является проверкой PostgreSQL или других компонентов платформы.

### Проверка текста

`POST /validate-text` принимает текст и возвращает исходное значение вместе с рассчитанной длиной:

```json
{
  "text": "Enterprise GenAI Platform"
}
```

```json
{
  "text": "Enterprise GenAI Platform",
  "length": 25
}
```

### Семантическая близость

`POST /semantic-similarity` принимает два непустых текстовых значения `left` и `right`. Для этого контракта используется удаление начальных и конечных пробелов с последующей проверкой длины: **от 1 до 1000 символов** на каждое поле.

Запрос:

```json
{
  "left": "The application stores data in PostgreSQL.",
  "right": "The system persists information in a PostgreSQL database."
}
```

Ответ:

```json
{
  "score": 0.75979
}
```

Значение приведено как пример результата модели; небольшие численные различия между средами допустимы. Поле `score` обязательно в контракте взаимодействия с Core API.

FastAPI использует Pydantic для проверки входных данных. Некорректные запросы к самому Python сервису получают HTTP `422`. Публичный маршрут Core API `/ai/semantic-similarity` применяет собственную проверку запроса и для некорректного ввода возвращает HTTP `400`.

## Интеграционный контракт с Core API

В .NET используется типизированный `HttpClient` с настройками `AiOrchestrator:BaseUrl` и `AiOrchestrator:TimeoutSeconds`. При отправке запроса передаётся `CancellationToken` исходной операции.

Обработка ошибок сосредоточена на интеграционной границе: технические исключения классифицируются клиентом, а `AiServiceExceptionHandler` формирует безопасный ответ в формате **ProblemDetails**.

| Условие | Ответ Core API |
| --- | --- |
| Успешное выполнение | `200 OK`, JSON с `score` |
| Ошибка проверки входного запроса Core API | `400 Bad Request` |
| Python вернул HTTP-ошибку, некорректный JSON или ответ без `score` | `502 Bad Gateway` |
| Нет соединения с Python | `503 Service Unavailable` |
| Превышено время ожидания исходящего HTTP-вызова | `504 Gateway Timeout` |
| Вызывающий код отменил операцию | Отмена распространяется, а не маскируется под `504` |

Внешний ответ не включает внутренний адрес зависимости, подробности исключения или диагностический текст Python. Для технического анализа используются серверные журналы.

### Сквозная идентификация запросов

Для сопоставления событий используется заголовок `X-Correlation-ID`:

- Core API принимает корректный идентификатор либо создаёт новый UUID.
- Допустимы латинские буквы, цифры, дефис, подчёркивание и точка; максимальная длина 128 символов.
- `CorrelationIdPropagationHandler` передаёт идентификатор в исходящем HTTP запросе к Python.
- FastAPI сохраняет его в контексте запроса, добавляет в ответ и включает в журналы.
- При возникновении интеграционной ошибки Core API записывает категорию сбоя и тот же идентификатор.

Заголовок используется **для диагностики**, а не для аутентификации или принятия решений о доступе. Содержимое пользовательских текстов не требуется включать в технические журналы для сопоставления запросов.

## Развёртывание и конфигурация

AI Orchestrator работает в отдельном контейнере `ai-orchestrator`. Образ собирается из `src/ai-orchestrator/Dockerfile` на основе Python 3.13; PyTorch устанавливается в варианте **CPU-only**. Приложение запускается от непривилегированного пользователя `app` и слушает порт `8000`.

В локальном `compose.yaml` используются следующие параметры:

| Параметр | Значение / смысл |
| --- | --- |
| `HF_HOME` | `/home/app/.cache/huggingface` — каталог кеша моделей |
| `huggingface_cache` | Именованный том Docker, сохраняющий скачанные файлы модели между пересозданиями контейнера |
| `ai-orchestrator:8000` | Внутренний адрес сервиса в сети Docker Compose |
| `127.0.0.1:8000` | Адрес прямого доступа к Python на компьютере разработчика |
| `AiOrchestrator__BaseUrl` | `http://ai-orchestrator:8000` адрес зависимости для Core API внутри Compose |
| `AiOrchestrator__TimeoutSeconds` | `30` время ожидания HTTP клиента Core API в секундах |

Для первоначальной загрузки публичной модели требуется доступ к Hugging Face. Переменная `HF_TOKEN` может использоваться в средах с ограничениями на неаутентифицированные обращения, но не является обязательной для данной публичной модели.

При проверке готовности контейнера используется `GET /health`. Поскольку загрузка модели происходит до начала обслуживания HTTP, статус `healthy` означает, что сервис завершил начальную инициализацию. Конфигурация Compose предусматривает льготный период запуска для первой загрузки модели.

**AI Orchestrator не подключается к PostgreSQL и не выполняет EF Core migrations.** Эти обязанности принадлежат Core API и отдельному одноразовому сервису `db-migrator`. В общей конфигурации Core API запускается после успешного завершения мигратора и готовности AI Orchestrator.

Для сохранения базы данных и файлов модели при остановке окружения используются тома `postgres_data` и `huggingface_cache`. Удаление томов командой `docker compose down -v` приводит к потере соответствующих локальных данных.

## Эксплуатационные свойства

**Изоляция отказов.** Недоступность Python не должна приводить к остановке Core API. При сетевом отказе публичный интерфейс сообщает о временной недоступности зависимости; после восстановления Python последующие обращения обслуживаются без обязательного перезапуска Core API.

**Воспроизводимость модели.** Кеш Hugging Face ускоряет повторный запуск, но сам по себе не фиксирует версию исходных весов и всей цепочки зависимостей. Для сред с требованиями к строгой воспроизводимости необходимо отдельно контролировать версии Python пакетов и ревизию модели.

**Вычислительная нагрузка.** Текущая реализация ориентирована на локальный вывод на CPU. Значения времени ответа и допустимая параллельность зависят от оборудования и нагрузки; гарантии производительности не определяются одним фактом наличия HTTP healthcheck.

**Границы доступа.** Прямой порт Python в локальном Compose привязан к интерфейсу `127.0.0.1`. Внешним клиентам следует предоставлять согласованный интерфейс Core API, не открывая вычислительный сервис напрямую без необходимых сетевых ограничений и механизмов защиты.

## Проверка изменений

Для сервиса предусмотрены модульные тесты и проверки HTTP контрактов с подменой зависимостей модели. Это позволяет проверять валидацию, маршруты и семантику вычислительной службы независимо от скачивания весов. Типы проверяются с помощью `mypy`.

Из каталога `src/ai-orchestrator` в настроенном виртуальном окружении:

```powershell
python -m pytest -v
python -m mypy src tests
```

Тесты интеграционной границы на стороне .NET проверяют обработку HTTP ошибок, тайм ауты, отмену, корректность ответов, `ProblemDetails` и передачу Correlation ID. Они используют управляемые HTTP обработчики и не требуют работающего Python сервиса.

Полный сценарий взаимодействия проверяется в Docker Compose через публичный маршрут Core API с реальной моделью. Он охватывает передачу запроса между контейнерами, вычисление сходства, сквозной идентификатор запроса и восстановление после временной недоступности Python.
